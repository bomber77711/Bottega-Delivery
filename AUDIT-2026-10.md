# Bottega Delivery — Frontend audit & fixes (October 2026)

Audit of the production site (bottega-delivery.com, identical to this repo) with a headless browser across 25 routes, every image URL, every map marker and the production build. Everything below was found and fixed in this change set unless listed under "Still open".

## 1. Products page "blank" tiles
| Finding | Fix |
|---|---|
| 2 Unsplash photo IDs were dead (404): every **Cured Meats** and **Truffle** image (category tiles + 5 products) rendered as a broken icon with alt text. Same for the Truffle Hunt experience, the Pasta/Truffle producer heroes, the Puglia network image and a Base44 olive-oil image (11 dead references in total). | All images self-hosted under `public/img/`, dead ones replaced. |
| ~25 other image IDs were valid photos of the **wrong subject** (likely invented by the AI builder): Sicily = man in a VR headset, Sardinia = aurora borealis, Piedmont = portrait of a stranger, Honey = watermelon, Trofie al pesto = a chair, Spirits = Johnnie Walker, Calabria = Thai karst cliffs, Pesto = kebab skewers, Nuts = bookshelf, Cheese = camping gear… | Replaced with correct photos (CC BY / BY-SA via Openverse, credited on /About and in `public/img/CREDITS.md`, or Unsplash). |
| One photo per category: 6 cheeses shared one picture, 4 cured meats another, etc. | Every product has its own photo (`/img/products/<id>.webp`). |
| Balsamico, Pesto and Carnaroli rice were filed under "Preserves"; pistachios under "Sweets". | New taxonomy: Pasta & Rice, Condiments, Nuts & Sweets. |
| The map's deep links (`/products?q=Chianti`) were ignored: the router used an old copy of the page, while the newer copy with `?q=` support sat unused in `components/`. Same for Recipes, Experiences and Ingredient (the newer Ingredient file had 15 more ingredients). | Newer versions promoted into `pages/`, duplicates deleted. Filters now live in the URL: `?q= &category= &region= &cert= &sort=`. |
| Fixed 8-column category grid, no empty state, no way to clear filters. | Responsive grid (2-up on phones, swipeable categories), removable filter chips, helpful empty state, region filter and sort. |
| Safety net | `<SmartImage>` + a global `<img>` error handler: a failed image now shows a branded placeholder, never a broken icon. |

## 2. Interactive map
| Finding | Fix |
|---|---|
| Downloaded a **2.75 MB GeoJSON from raw.githubusercontent.com** on every first visit (71k vertices); if GitHub was slow or rate-limited, the map stayed on "Loading atlas…" forever. | Bundled simplified TopoJSON (57 KB, all islands kept). Map renders instantly with no external dependency. |
| Home stored the mouse position in React state on every `mousemove`, re-rendering the whole page and re-computing 1.1 MB of SVG path strings (~64 ms CPU) per mouse move: visible hover jank. | Paths computed once per size and memoised; tooltip positioned via ref; region paths are memoised components. |
| **104 of 153 marker destinations were broken**: 22 linked to "Ingredient not found", the rest opened unfiltered lists, with junk queries from a "longest word" heuristic (`?q=Experience`, `?q=Rosso`, `?q=Heritage`). | Clicking a marker opens a detail card with links resolved against the real catalogue (`src/lib/catalog.js`). Each count matches the destination page exactly. `npm run audit:links` verifies all 160 markers / 372 links. |
| Markers were arbitrary offsets from regional capitals (Barolo sat near Valle d'Aosta). | All 160 markers have real town coordinates (Barolo, Pienza, Cabras, Bronte…), each verified inside its region polygon, plus automatic de-overlap. |
| When zoomed, other regions' markers and the centroid dot were scaled ×5 into giant blurry circles; the zoom ignored the side panel and overlays, so the region was clipped. | Markers render in an unscaled overlay at constant size; zoom frames the region inside the space left by the panel/controls (desktop and mobile); smooth rAF animation; `prefers-reduced-motion` respected. |
| Hover tooltip sat 130 px above the cursor, covering the region being hovered. | Follows the cursor with edge-flipping. |
| Choropleth colours were near-identical; legend colours didn't match the map and were overlapped by the Discover button. | Visible 4-step density scale exported from the map and reused by the legend. |
| Mobile: the 380 px panel was wider than the phone; controls overflowed; enlarged marker hit-areas covered the regions, so tapping a region didn't open it. | Bottom-sheet panel, scrollable layer chips, tap a region → zoom, then tap markers. |
| No keyboard access; selected region not shareable; Back button did nothing. | Regions/markers are focusable (Enter/Space, Esc peels back layers). Selection is in the URL (`/?region=toscana`), so it can be shared and Back works. |
| Region panel: experience rows, ingredient chips and the ♥ button did nothing. | All clickable (experiences, ingredient guides, saved favourites). |

## 3. Platform
| Finding | Fix |
|---|---|
| **Ask Bottega AI returned HTTP 405 in production**: `ask-bottega.js` sat at the repo root, but Vercel only deploys functions from `/api`. | Moved to `api/ask-bottega.js`. Model configurable via `ANTHROPIC_MODEL` env var (default `claude-sonnet-5-5`); requires `ANTHROPIC_API_KEY` in Vercel. |
| **Brand fonts never loaded**: `globals.css` (Playfair Display / DM Sans / DM Mono, colour tokens, `fadeSlideIn`/`dashMove`/`badgePop` keyframes) was never imported. Production rendered system fallback fonts. | Fonts loaded via `<link>` + preconnect in `index.html`; cleaned `globals.css` imported. |
| Images: ~59 MB of remote PNG/JPG (Base44 region heroes ≈ 1.9 MB each), plus Base44-hosted assets that disappear if that account lapses. | All self-hosted WebP: 12 MB total on disk, region heroes ≈ 200 KB each. |
| One 606 KB JS bundle. | Route-level code splitting (all pages except Home lazy-loaded). |
| Region pages linked every producer to `/producers/undefined`; creator "favourite producers" were always empty; producer pages' "recipes from this region" were always empty (recipes had no region id). | Fixed (slug ids, `recipe.region`). |
| "Discover" float linked regions to `/ExploreMap` (a redirect) and producers to the generic list; it covered content on phones. | Deep links fixed; compact on phones, hidden while the map sheet is open. |
| Stale root-level duplicates (`App.jsx`, `Layout.jsx`, `main.jsx`, `pages.config.js`, `globals.css`) had already diverged from `src/`; dead `ExploreMap` page; 18 lint errors; React key/nesting warnings. | Removed / fixed. `npm run check` = lint + link audit + build. |
| SEO | Real title, description, Open Graph/Twitter tags, share image. |

## Still open (product decisions, not code)
1. **Catalogue coverage**: 70 of 160 map markers have no product, recipe or experience yet (e.g. all of Sardinia, Umbria, Trentino, Friuli, Basilicata, Molise). Their cards say so honestly and link to the region. Adding ~1 product per marker closes the gap.
2. **Real brand names**: the demo catalogue lists real companies (Giacomo Conterno, Felicetti, Di Martino, Vannulo, Berlucchi, Bisol, Florio, Muraglia…) with invented products and prices, implying they sell on Bottega. Replace with onboarded producers or clearly mark the catalogue as a demo before showing it to investors or the press.
3. Map statistics ("450 producers", per-region counts) are hard-coded marketing figures, not counts of the catalogue.
4. Checkout/Stripe is a front-end mock; the cart is client-side only.
5. Unused dependencies (three, react-quill, stripe, jspdf, html2canvas, react-leaflet, moment…) can be removed from `package.json` to speed up installs; they are not bundled.
